--------------------------------------------------
3. CONCEPTO CLAVE: $1 (ARGUMENTOS POSICIONALES)
--------------------------------------------------
Cuando se ejecuta:  ./sysinfo.sh net
Bash separa automáticamente la línea en piezas y las guarda en variables
especiales YA POBLADAS, sin que el script tenga que declararlas:

    $0  → nombre del script (./sysinfo.sh)
    $1  → primera palabra después del nombre (net)
    $2  → segunda palabra, si hubiera

Prueba de concepto usada para verificarlo:
    #!/bin/bash
    echo "El valor de \$1 es: $1"

Con esto se corrigió el script:
    args="$1"
    case "$args" in
      memory) ... ;;
      disk)   ... ;;
      net)    ... ;;
      *)      echo "No valido" ;;
    esac

NOTA: iba a probarse con nombres tipo "1)" o "y)" en el case en vez de
"memory)"/"disk)"/"net)" - se aclaró que el nombre debe coincidir con la
PALABRA que realmente se escribe como argumento (ej: si el usuario escribe
"net", el case debe tener literal "net)", no un número o letra suelta que
no tenga relación con lo escrito).

8. INSTALACIÓN DE VSCODIUM (AUR, proceso manual)
--------------------------------------------------
Motivo: seguir un curso de Bash en video que usa VS Code como editor.
VS Code no está en los repos oficiales de Arch (licencia de Microsoft),
así que se instaló su alternativa open source: VSCodium.

ERROR INICIAL: se clonó "vscodium-bin-git" (con "-git" de más), que resultó
ser un paquete AUR distinto (o vacío/no encontrado del todo). Se limpió con:
    rm -rf vscodium-bin-git

Para confirmar el nombre exacto del paquete, se usó la API del AUR:
    curl -s "https://aur.archlinux.org/rpc/v5/search/vscodium" | grep -o '"Name":"[^"]*"'

Esto mostró varias variantes existentes: vscodium, vscodium-bin,
vscodium-git, vscodium-insiders, vscodium-*-marketplace, etc.
- "-bin"  → binario ya compilado (rápido de instalar)
- "-git"  → compila desde el código fuente más reciente (lento)
- "-marketplace" → variante parcheada para usar el marketplace oficial de
  extensiones de Microsoft en vez de Open VSX (técnicamente contra los
  términos de uso de Microsoft, se optó por NO usar esta variante)

Instalación correcta:
    git clone https://aur.archlinux.org/vscodium-bin.git
    cd vscodium-bin
    cat PKGBUILD        → revisión de seguridad antes de compilar (repasar
                            que la URL de descarga sea la oficial del
                            proyecto, sin nada sospechoso)
    makepkg -si          → compila e instala (-s dependencias, -i instala
                            el paquete final)

====================================================
CONCEPTOS CLAVE PARA RECORDAR
====================================================
- $1, $2... son variables automáticas de bash que ya vienen pobladas al
  ejecutar el script con argumentos; no se declaran a mano.
- case "$variable" in patrón) comandos ;; esac es más limpio que múltiples
  if/elif para menús de opciones basados en texto.
- Comparación numérica en bash usa -gt, -lt, -eq (no >, < que comparan texto
  en algunos contextos).
- while read -r var1 var2... recorre una salida línea por línea, repartiendo
  cada línea en las variables indicadas según los espacios.
- Código duplicado en un script es señal de que hace falta una función.
- El AUR requiere revisar el PKGBUILD antes de compilar (medida de
  seguridad real, no solo teórica, por los ataques de paquetes maliciosos
  reportados en el AUR).
- Nombres de paquetes AUR parecidos (paquete vs paquete-bin vs paquete-git)
  son proyectos independientes, hay que verificar el nombre exacto antes
  de clonar (con la API de búsqueda del AUR si hay duda).
